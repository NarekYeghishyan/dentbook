# ADR-0010. Бот Telegram и Mini App врача

Дата: 2026-09-18
Статус: принято

## Контекст

Шаг 7: привязка врача, алерты с кнопками, расписание, закрытие времени, запись своих
клиентов. Обязательные требования — в §8. Уточнения: один домен с путями (Q14), в карточке
врача ссылка копируется и показывается QR-кодом (Q15), запись с подтверждением ждёт врача и
напоминает ему через N часов (Q12, N = 2), языки en/ru/hy (Q6).

## Решение

- **Адреса.** Вебхук — `PUBLIC_BASE_URL/telegram/webhook`, Mini App —
  `PUBLIC_BASE_URL/miniapp/`. Оба отдаёт тот же API, nginx ничего не добавляет. Бота
  настраивает скрипт `apps/api/src/telegram-setup.ts`: `setWebhook` с `secret_token` и
  `allowed_updates` = message и callback_query, кнопка меню `web_app` на Mini App, описание
  `/start` на трёх языках. Скрипт сверяет `TELEGRAM_BOT_USERNAME` с токеном. Запуск
  повторяемый: после выдачи токена или смены домена.
- **grammY — клиент Bot API и типы.** Worker отправляет сообщения через `Api`, API
  использует типы `Update`. Обновлений два вида: `/start` и кнопка «Подтвердить». Их
  разбирает свой обработчик, без `Bot`/`Composer`: дедупликация по `update_id` и работа с БД
  должны идти в нашем порядке. Строку дедупликации обработчик удаляет, если упал, — тогда
  повтор от Telegram обработается заново.
- **Вебхук** сверяет заголовок `X-Telegram-Bot-Api-Secret-Token` за постоянное время и
  отвечает 200 на всё, что принял. Бот работает только в личных чатах.
- **Исходящие сообщения** — только через BullMQ-очередь `telegram`: 6 попыток,
  экспоненциальная пауза от 5 с, не больше 25 сообщений в секунду. На 403 worker ставит
  `telegram_blocked`, помечает уведомление неудачным и больше не повторяет. Флаг снимается,
  когда врач снова пишет боту `/start`.
- **Привязка.** Токен — 32 случайных байта (base64url). В БД хранится только SHA-256,
  срок — 24 часа, токен одноразовый. Аккаунт Telegram, уже привязанный к другому врачу,
  отклоняется. В панели: «Создать ссылку», копирование, QR-код (`qrcode` грузится отдельным
  чанком по требованию). Пока ссылка открыта, карточка раз в 5 с перечитывает врачей и сама
  переходит в «Подключён».
- **Алерты.** О новой записи — с кнопками «Открыть расписание» (`web_app`) и
  «Подтвердить», если запись ждёт подтверждения. Об отмене клиентом. Напоминание о
  неподтверждённой записи — отложенная задача через 2 часа. Worker пропускает её, если запись
  уже не `pending`. Строка в `notifications` на каждое сообщение.
- **Mini App** — React + TanStack Query + Tailwind, цвета из темы Telegram
  (`--tg-theme-*`). Три вкладки: расписание дня, закрыть время, новая запись. Язык — выбор
  врача (`dentists.locale`), иначе профиль Telegram, иначе язык клиники. Время записей — в
  поясе офиса, закрытое время — в поясе клиники (§2.3).
- **Язык врача** — врач выбирает его сам в Telegram: команда `/language` в боте (кнопки
  подписаны самим языком: English, Русский, Հայերեն) или переключатель в шапке Mini App
  (`PATCH /v1/miniapp/me`). Выбор один на обе поверхности, хранится в `dentists.locale`
  (NULL — не выбирал). На нём же бот пишет алерты и описания записей, поэтому
  `describeAppointment` отдаёт язык врача записи, а `clinicLocale` остаётся для сообщений
  другому врачу при переносе.
- **Вход в Mini App** — заголовок `Authorization: tma <initData>` на каждом запросе, без
  своей сессии и cookie. Подпись и свежесть (не старше часа, §8) проверяются каждый раз.
  Врач и клиника берутся только из подписи (§2.2).
- **Закрыть время** нельзя, если на нём есть записи. Ответ — 409 `slot_taken` со списком,
  переносит регистратура (§8). Проверка и вставка идут под advisory-lock врача.
- **Своя запись врача** — без SMS-кода, сразу `confirmed`, `source = 'telegram'`. Без
  минимального запаса по времени (врач записывает и на ближайший час), но через тот же
  движок слотов и то же ограничение `EXCLUDE`. Клиент ищется по телефону в клинике.
- **Телефон клиента от врача** (2026-10-03, по просьбе заказчика) — необязательный, любой
  текст до 50 знаков, формат не проверяется ни в Mini App, ни в API (`anyPhoneSchema`).
  Номер, который читается как E.164 (`toE164`), приводится к нему; остальное хранится как
  введено; пусто — клиент без номера (`patients.phone` NULL). В БД вместо CHECK на E.164 —
  `patients_phone_not_blank`: NULL или непустой текст. Регистратура в журнале вводит номер
  так же в любом виде, но обязательно (`freePhoneSchema`, с 2026-10-04). Форма на сайте
  по-прежнему требует E.164: она подтверждает номер SMS-кодом.
- **Клиент без номера** не находится по телефону: NULL в уникальном ключе
  `(clinic_id, phone)` не совпадает ни с чем, и у каждой такой записи свой клиент. Его имя
  врач правит на месте. Если врач убирает номер у клиента с номером, запись получает
  нового клиента без номера, а карточка клиента с номером остаётся как была.
- **Тест «Готово»** — `apps/api/test/e2e/miniapp.e2e.test.ts`: собранный Mini App в
  Chromium против настоящего API. `telegram-web-app.js` подменяется заглушкой с initData,
  подписанной тестовым токеном. Бот проверяется интеграционными тестами вебхука.

## Последствия

- Mini App, открытый дольше часа, получает 401 и просит открыть расписание заново. Это
  цена требования о свежести `auth_date`. Продлевать сессию своим токеном — отдельная задача.
- Текст кнопки меню у Telegram один на бота — английский. Команды (`/start`, `/language`)
  описаны на трёх языках.
- Язык врача и язык клиники разошлись: клиент клиники по-прежнему получает SMS на языке
  клиники, врач — на своём. Общего «языка записи» нет и быть не должно.
- Mini App не регистрируется в @BotFather (`/newapp`): кнопки меню и `web_app` хватает.
  Прямая ссылка `t.me/<bot>/<app>` не используется.
- На номер не в E.164 SMS клиенту не уходят: провайдер его не примет, и worker помечает
  уведомление `cancelled` с причиной `phone_not_e164`; клиенту без номера — тоже, с
  причиной `no_phone`. В алертах врачу вместо «имя, телефон» тогда только имя
  (`{contact}` в шаблонах). Клиент ищется по номеру как
  введён: «077 12-34-56» и «077123456» — два разных клиента. Если регистратура выберет в
  журнале клиента без номера, форма попросит ввести номер.
- Без `TELEGRAM_BOT_TOKEN` бот, вебхук и `/v1/miniapp` выключены. Панель на «Создать
  ссылку» показывает, что бот не настроен (503).
