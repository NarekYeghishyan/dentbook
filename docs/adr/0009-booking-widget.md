# ADR-0009. Форма записи (виджет), капча и SMS

Дата: 2026-09-18
Статус: принято

## Контекст

Шаг 6: форма записи для сайта клиники — верификация телефона, капча, адаптивность,
бандл меньше 50 КБ gzip, запись end-to-end на тестовой странице. Q5: клиенты клиник в США,
капча — Cloudflare Turnstile, SMS-провайдер — на моё предложение (Twilio).

## Решение

- **Встраивание** — один тег `script` с `src=".../widget/dentbook-widget.js"`, ключом в
  `data-key` и местом формы в `data-target`. Адрес API — origin самого скрипта, язык —
  `data-locale` или язык клиники. Готовый код показывает панель на странице «Сайт». Ручной вызов —
  `DentBook.mount(element, { key, apiBase })`.
- **Всплывающее окно** (2026-10-02, по запросу владельца) — `data-mode="popup"`: форма
  открывается поверх страницы кликом по кнопке или ссылке сайта с классом `dentbook-open`
  (`data-trigger` — свой CSS-селектор). Клик слушается на документе, поэтому работают и
  кнопки, добавленные позже. Окно — нативный `<dialog>` с `showModal()` внутри того же
  Shadow DOM: затемнение, Esc, удержание и возврат фокуса даёт браузер, своего кода для
  этого нет. В API окно не ходит до первого открытия — кнопки стоят на многих страницах, а
  запросы считаются в лимит ключа. Режим хранится у ключа (`api_keys.embed_mode`), но
  только чтобы панель показала нужный код: виджет берёт режим из атрибутов кода, а не из
  `/config`. Так один ключ может работать и на странице записи, и в окне на остальных
  страницах, а смена режима в панели не ломает уже вставленный код.
  TODO: класс кнопок общий для всех ключей — свой класс у ключа, если клиника попросит.
- **Изоляция** — Shadow DOM, стили строкой (ADR-0002): стили сайта не ломают форму, и
  наоборот. Цвет — `theme.primary_color` клиники.
- **Без фреймворка и без zod.** Из `@dentbook/shared` виджет берёт только типы и
  `shared/domain`, `shared/errors`. Бандл — 8 КБ gzip. Бюджет проверяет
  `pnpm --filter @dentbook/widget size`: сборка падает, если бандл больше 50 КБ. Эта проверка
  встроена и в `Dockerfile`.
- **Путь клиента:** услуга → офис (если офисов несколько) → день и время (окно 14 дней) →
  холд с обратным отсчётом → имя, телефон, email → капча → SMS-код → готово, с отменой по
  токену. На `slot_taken` форма показывает альтернативы, на `hold_expired` возвращает к
  выбору времени. Ответ 503 означает, что SMS не настроены, и клиент видит «запись сейчас
  недоступна».
- **Телефон** приводится к E.164: 10 цифр — номер США, с «+» — любая страна.
- **Капча** — Turnstile. Скрипт Cloudflare грузится, только если `GET /config` вернул
  `captcha`, и в бюджет бандла не входит. Сервер проверяет токен (`siteverify`) до лимита
  по номеру и до отправки SMS. Без `CAPTCHA_*` капча выключена.
- **SMS** — Twilio REST без SDK (`TwilioSmsSender`). Отправитель — номер или Messaging
  Service (`MG…`, для 10DLC). Без `SMS_PROVIDER` отправка кода отвечает 503. Номер
  получателя в ошибки и логи не попадает.
- **Раздача** — бандл отдаёт API на `/widget/` с коротким кешем (5 минут: адрес постоянный,
  обновление должно доходить быстро) и `Cross-Origin-Resource-Policy: cross-origin`.
- **Сквозной тест** — Playwright как библиотека внутри Vitest
  (`apps/api/test/e2e/booking.e2e.test.ts`, `pnpm test:e2e`). Настоящий API на
  Testcontainers, тестовая страница `apps/widget/test-page` на другом origin, Chromium.
  Отдельно от `pnpm test`: нужен собранный виджет и установленный браузер
  (`pnpm exec playwright install chromium`). Отдельный e2e-фреймворк не вводился — это не
  замена Vitest из §3.

## Последствия

- Без ключей Twilio и Turnstile (Q5) на стенде форма доходит до ввода телефона и честно
  сообщает, что онлайн-запись недоступна. Ключи — переменные окружения, код менять не нужно.
- Turnstile внутри Shadow DOM проверен только по документации: тест с настоящим скриптом
  Cloudflare — после выдачи ключей.
- Номера вне США клиент вводит с «+». Если появятся клиники в других странах — страна по
  умолчанию станет настройкой клиники.
