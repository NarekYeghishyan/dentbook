# ADR-0011. SMS-уведомления клиентам и напоминания

Дата: 2026-09-18
Статус: принято

## Контекст

Шаг 8: SMS-провайдер, шаблоны, напоминания за 24 ч и за 2 ч, снятие напоминаний при
отмене, повторные попытки. Q12 добавляет SMS клиенту, когда запись подтвердили. Провайдер —
Twilio (Q5, ADR-0009). Он уже отправлял коды подтверждения из API.

## Решение

- **Клиент Twilio** переехал в `@dentbook/shared/sms`: им пользуются API и worker. Отказ
  провайдера — `SmsError` с кодом. Флаг `permanent` у 4xx, кроме 429: неверный номер,
  отписка, ошибка настройки. 429, 5xx и сбой сети — временные.
- **Коды подтверждения** API отправляет по-прежнему сразу, без очереди. Клиент ждёт код на
  экране, и ошибку провайдера нужно показать ему сразу.
- **Уведомления** идут через BullMQ-очередь `sms`. API пишет строку `notifications` и кладёт
  задачу, у которой id задачи совпадает с id строки. Напоминания — отложенные задачи.
  В задаче только этот id: телефон и текст worker читает из БД в момент отправки. Так в
  Redis неделями не лежат ПДн (§2.6), а текст соответствует записи на момент отправки.
- **Когда ставятся.** При создании записи — на сайте или врачом в Mini App — ставятся
  напоминания, время которых ещё не наступило. Время — точное смещение в UTC, 24 ч и 2 ч
  (`REMINDER_OFFSETS_MS`). Переход на летнее время его не сдвигает. Напоминания ставятся и
  для `pending`: worker отправит их, только если к сроку запись подтверждена. SMS «запись
  подтверждена» уходит при подтверждении в боте или в Mini App.
- **Снятие.** Когда клиент отменяет запись, API помечает её запланированные SMS `cancelled`
  и удаляет задачи из очереди. Worker перед отправкой ещё раз проверяет запись: задача,
  которую уже взяли в работу, удалению не поддаётся. Причина пропуска пишется в
  `last_error`: `appointment_<status>`, `visit_started`, `superseded`. Последнее — это
  напоминание за сутки, которое опоздало к сроку напоминания за 2 ч.
- **Повторы** (`SMS_JOB_OPTIONS`): 5 попыток с паузой 30 с, 1, 2 и 4 мин. Постоянный отказ
  сразу даёт `failed` без повторов (`UnrecoverableError`). Временный записывает попытку и
  код, `failed` ставится только после последней попытки. Отправленное хранит SID сообщения
  Twilio в `provider_message_id`.
- **Шаблоны** — в `apps/worker/src/i18n/{en,ru,hy}.json`: имя клиники, время в поясе офиса,
  офис. Услуга в текст не входит: SMS видно на экране блокировки. Язык — язык клиники.
- **Без провайдера** (`SMS_PROVIDER` пуст) API не ставит уведомления, worker не слушает
  очередь, коды отвечают 503 — как в Шаге 6. Переменные SMS нужны обоим процессам.

## Последствия

- Если отправка прошла, а запись о ней в БД упала, повтор отправит SMS второй раз. Это
  редкий случай, в журнале будет одна отметка.
- Перенос записи (Шаг 9) сделает то же, что отмена, плюс заново поставит напоминания:
  `appointmentCancelled` + `appointmentCreated` без алерта или отдельный метод.
- Q16 (дополнено 2026-09-18): напоминание, которое приходится на 21:00–8:00 по времени
  офиса, worker пропускает с причиной `quiet_hours`; подтверждение записи не задерживается.
  В конце каждого уведомления — строка об отписке (`sms.optOut`). SMS о записи,
  подтверждённой сразу, не шлётся.
- Повтор алерта врачу о неподтверждённой записи (Q12) остаётся в очереди Telegram
  (ADR-0010). Регистратура увидит такие записи в журнале (Шаг 9).
