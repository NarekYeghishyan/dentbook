# ADR-0008. Публичный API, холды и кеш доступности

Дата: 2026-09-18
Статус: принято

## Контекст

Шаг 5: ключи `pk_*`, публичный API `/v1/public` (§7), проверка Origin (§2.5), лимиты,
холды и их истечение, `slot_taken` с альтернативами (§2.1), кеш доступности (§6).
CLAUDE.md задаёт маршруты и коды ошибок, но не форму полей, порядок проверок, устройство
холда, лимиты и хранение SMS-кодов. Q4 дал числа, Q11 — защиту буфера в БД.

## Решение

- **Контракт — snake_case** (`hold_id`, `expires_at`, `service_id`), как названо в §7.
  Админский API обслуживает только нашу панель и остаётся в camelCase.
- **Буфер в БД (Q11).** Колонка `appointments.blocked_until = end_at + buffer_min`
  заполняется кодом (`blockedUntil()`), CHECK сверяет. EXCLUDE строится по
  `tstzrange(start_at, blocked_until)`. Выражение прямо в индексе невозможно:
  `timestamptz + interval` не IMMUTABLE. Текст §2.1 в CLAUDE.md обновлён.
- **Ключ и Origin.** `Authorization: Bearer pk_…` → ключ не отозван, клиника активна,
  иначе `401 invalid_key`. Затем `Origin` должен быть в `allowed_origins`, иначе
  `403 origin_not_allowed`; запрос без Origin (не из браузера) тоже 403. CORS-заголовок
  ставится до проверок, чтобы форма прочла код ошибки; данных в ответе нет, пока проверки
  не пройдены. Preflight отвечает без ключа — браузер не шлёт с ним Authorization.
- **Лимиты (Q4).** 60 запросов в минуту на ключ — фиксированное окно, счётчик в Redis.
  10 холдов и 10 SMS-кодов в минуту с IP — `@fastify/rate-limit` с хранилищем в Redis.
  Кодов на один номер — не больше 5 в час: SMS платные и их накручивают. `trustProxy` —
  одно звено (nginx), иначе IP подделывается через `X-Forwarded-For`.
- **Публичный API есть только при Redis**: лимит на ключ без общего счётчика не выполнить.
  Тесты без Redis собирают приложение без `/v1/public`.
- **Холд — строка `appointments` со `status = 'hold'`** (ADR-0003). Время проверяется по
  свежему расчёту без кеша. Врач назначается по §6 (`pickDentist`); если его время заняли
  между расчётом и вставкой (`23P01`), пробуется следующий кандидат. Если не подошёл никто —
  `409 slot_taken` и до 6 ближайших свободных слотов дня в поле `alternatives`.
- **Холд и закрытие времени под одним advisory-lock на врача** (`lockDentist`): внутри
  блокировки холд проверяет, что время не закрыто блоком, а блок — что на время нет
  записей. Двойную бронь исключает по-прежнему только EXCLUDE.
- **Истечение холда.** Расчёт доступности не считает просроченный холд занятым. Новый холд
  сам снимает мешающий просроченный (`expireStaleHolds` в той же транзакции). Worker раз в
  минуту переводит все просроченные в `expired` и сбрасывает кеш их врачей. Отмена холда
  клиентом (`DELETE /holds/:id`) освобождает слот сразу.
- **SMS-код**: 6 цифр, 5 минут, 3 попытки (Q4). В БД — HMAC-SHA256 кода с ключом,
  производным от `JWT_SECRET`: отдельная переменная не нужна. Попытка списывается отдельным
  запросом до сравнения и остаётся списанной. Один код — одна запись. Текст SMS — в файлах
  переводов API (`apps/api/src/i18n`).
- **Подтверждение** — одна транзакция: израсходовать код → карточка клиента по телефону
  (upsert) → холд в `pending`/`confirmed` по настройке клиники (Q9), только если он ещё
  `hold` и не истёк. Иначе `410 hold_expired`, и код не расходуется. Из двух одновременных
  подтверждений одного холда проходит одно.
- **Статус и отмена клиентом** — по `public_token` записи. Холд по публичному адресу не
  виден. Отменить можно будущую `pending`/`confirmed`; повторная отмена отвечает текущим
  состоянием. Токен из query в логах заменяется на `[redacted]`.
- **Кеш слотов** — Redis, TTL 60 с (§6). Ключ — формат §6 плюс филиал в конце:
  `avail:{clinic}:{dentist}:{date}:{service}:{location}`. Без филиала у врача, работающего в
  двух филиалах, слоты смешались бы; префикс для сброса остаётся как в §6. Сброс по врачу —
  при записях, холдах, шаблоне, исключениях, услугах и активности врача. По клинике — при
  изменении настроек клиники, филиала или услуги. Сбой Redis не ломает ответ.
- **Без SMS-провайдера** `POST /verifications` отвечает `503`. Провайдер — Шаг 6 (Q5).

## Последствия

- Слот, закешированный пока холд был жив, может до 60 с выглядеть занятым после истечения:
  worker сбрасывает кеш раз в минуту. Сама запись на это время работает сразу.
- В `slot_taken` показываются альтернативы только того же дня.
- Код ошибки `slot_taken` отвечает и на попытку закрыть время с записями (ADR-0007).
- TODO(Шаг 6): капча (Turnstile) на `POST /verifications`, реальный SMS-провайдер.
- TODO(Шаг 7–8): алерт врачу и SMS клиенту после записи, снятие напоминаний при отмене.
