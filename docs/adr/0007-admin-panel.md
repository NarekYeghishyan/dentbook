# ADR-0007. Панель клиники: раздача, время, переводы

Дата: 2026-09-18
Статус: принято

## Контекст

Шаг 4: панель клиники на React (CLAUDE.md §3) и админский API для филиалов, врачей, услуг
и расписания. CLAUDE.md не задаёт, кто раздаёт собранную панель, в каком поясе вводится
время исключений, как устроены переводы (Q6 — JSON и `t()`) и как отвечать, когда время
закрыть нельзя (§8).

## Решение

- **Раздача.** Собранную панель (`vite build`, `base: /admin/`) отдаёт процесс API через
  `@fastify/static`, если задан `ADMIN_DIST_DIR`. Один домен с API (Q14): cookie сессии
  без CORS, nginx на хосте не меняется. Хешированные файлы кешируются на год, `index.html`
  — `no-cache`. Страницы идут с CSP (`script-src 'self'`, `frame-ancestors 'none'`).
  Сборка панели — шаг `Dockerfile`.
- **Время** вводится и показывается в поясе филиала, а если его нет — клиники (§2.3), а не
  браузера. Перевод идёт тем же `@dentbook/core` (`zonedTimeToUtc`), что считает слоты на
  сервере; в API уходит ISO со смещением.
- **Переводы** — `apps/admin/src/i18n/{en,ru,hy}.json` и `t()`. Язык панели — выбор
  сотрудника в `localStorage`, по умолчанию язык браузера. `clinics.locale` — язык формы
  записи для клиентов, это отдельная настройка. Тест сверяет ключи и подстановки словарей
  и наличие текста для каждого кода ошибки §7.
- **Константы без zod.** Перечисления (`LOCALES`, `STAFF_ROLES`, роли, статусы) живут в
  `@dentbook/shared/domain`, который не тянет `zod`. Фронтенды берут значения оттуда, из
  корня `@dentbook/shared` — только типы. Для админки это −25 КБ gzip, для виджета
  (Шаг 6, бюджет 50 КБ) — обязательное условие.
- **Закрыть время с записями нельзя (§8)** — ни блоком, ни удалением дополнительного
  времени: `409 slot_taken` и рядом с `error` поле `conflicts` со списком записей. Проверка
  при удалении extra консервативная: считается любая запись в его интервале.
- **Недельный шаблон** заменяется целиком (`PUT`). Смены врача не пересекаются даже в
  разных филиалах (`findWeeklyOverlap` в core, ответ `400` с `overlap: [i, j]`). Уже
  существующие записи при смене шаблона не проверяются и не отменяются (§8).
- **Приоритет** — `PUT /dentists/order` с полным списком врачей: `priority` = 10, 20, 30…
  Частичный список — `400`, чужой или повторённый id — `404`.
- **Удаления сущностей нет.** Филиалы, услуги, врачи, сотрудники отключаются
  (`is_active`): на них ссылаются записи.

## Последствия

- Статику отдаёт Node. TODO(Шаг 10): nginx или CDN, если панель станет узким местом.
- Проверка через браузер (Playwright) пока — разовый сценарий вне репозитория: регистрация
  → офис → услуга → врачи → смены → перетаскивание → календарь → языки. Постоянные
  e2e-тесты и их инструмент — решение Шага 6, где они входят в критерий.
- Проверка конфликтов перед закрытием времени не под блокировкой: гонка с одновременной
  записью возможна. TODO(Шаг 5): общий advisory-lock на врача для записи и блока.
